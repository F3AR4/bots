# Learning Boundary & Self-Improvement Safety Framework

## 1. Core Principle: Paper-Bound Adaptation

The strategy PDF explicitly dictates that the system must **automatically update paper-trading rules based on empirical performance** without requiring manual human approval for each adjustment. However, to guarantee absolute safety and avoid algorithmic degradation, this self-improvement engine is governed by strict mathematical and environmental boundaries.

---

## 2. The Five-Tier Lifecycle Boundary

Strategy configurations and rules progress through five distinct lifecycle boundaries. Promotion across these boundaries is rigorously controlled:

```
┌─────────────┐     Auto      ┌───────────────┐     Paper      ┌─────────────┐
│  RESEARCH   │ ────────────> │   CANDIDATE   │ ─────────────> │    PAPER    │
│ (Hypothesis)│  (Rule Engine)│ (Validated)   │  (Active Sim)  │  (Live Sim) │
└─────────────┘               └───────────────┘                └─────────────┘
                                                                      │
                                                    Strict Human Gate │ (NO AUTO-PROMOTION)
                                                    Cryptographic Key │
                                                                      ▼
                                                               ┌─────────────┐
                                                               │   SHADOW    │
                                                               │ (Real Feed) │
                                                               └─────────────┘
                                                                      │
                                                    Explicit Authorization
                                                                      ▼
                                                               ┌─────────────┐
                                                               │ PRODUCTION  │
                                                               │ (Real Money)│
                                                               └─────────────┘
```

1. **RESEARCH**: Offline experimentation and statistical analysis of historical outcomes.
2. **CANDIDATE**: Rule proposals generated by the self-improvement engine backed by empirical trade evidence.
3. **PAPER**: Actively deployed in the local simulator for simulated \$5–\$20 allocations. **Autonomous adaptation is strictly bounded to this tier.**
4. **SHADOW**: Real-time evaluation alongside live markets without execution. (Requires manual operator flag).
5. **PRODUCTION**: Real-money trade execution. **Permanently disabled in Version 1.0.** The automated self-improvement engine has zero architectural access or permission to touch, activate, or promote any strategy into Production.

---

## 3. Immutability & Versioning Contract

- **Rule Sets are Immutable**: Once a `RuleSet` record is created and assigned a version (e.g., `v1.0.0`), its parameters cannot be updated in place.
- **Rule Changes are Audited**: Any adaptation spawns a new `RuleSet` record and logs a corresponding `RuleChange` entry detailing:
  - `oldRuleSetId`: Foreign key to parent ruleset.
  - `newRuleSetId`: Foreign key to newly instantiated ruleset.
  - `changedBy`: Identifier of the operating agent (`operator_agent` / `system`).
  - `reason`: Concise qualitative justification.
  - `evidenceSummary`: Quantitative data justification (e.g., *"Last 20 trades with spread > 3.5c lost an aggregate of -$42.10 paper PnL with a 25% win rate"*).
  - `beforeJson`: Verbatim snapshot of prior parameter values.
  - `afterJson`: Verbatim snapshot of new parameter values.
  - `expectedImprovement`: Projected metric shift (e.g., *"Reduce spread drag by 1.8%"*).
  - `timestamp`: UTC ISO-8601 timestamp.

## 4. Guardrails & Bounded Parameter Space

The autonomous rule updater operates inside an unbreachable parameter envelope ("guardrails"). No learned adjustment may breach these invariant bounds:

| Parameter | Minimum Bound | Maximum Bound | PDF Classification | Guardrail Purpose |
| :--- | :--- | :--- | :--- | :--- |
| `simulatedBetMin` | \$5.00 | \$5.00 | **[EXPLICIT]** | Preserves PDF lower bet constraint. |
| `simulatedBetMax` | \$20.00 | \$20.00 | **[EXPLICIT]** | Preserves PDF upper bet constraint. |
| `maxAllowedSpread` | 0.5 cents | 6.0 cents | **[IMPLIED]** | Prevents accepting illiquid, wide books. |
| `minMarketLiquidity` | \$100.00 | \$50,000.00 | **[IMPLIED]** | Ensures minimum liquidity floor. |
| `maxPriceDriftAllowed` | 0.5 cents | 5.0 cents | **[IMPLIED]** | Prevents chasing late-detected entries. |
| `minWalletConsistency`| 30.0 | 95.0 | **[IMPLIED]** | Disallows zero-consistency gamblers. |

### Forbidden Adaptations
The self-improvement engine is strictly prohibited from:
1. Disabling the `OneHitWonderPenalty` logic.
2. Elevating simulated bet sizes outside the \$5–\$20 window.
3. Suppressing or modifying historical journal entries, snapshots, or reports.
4. Bypassing error handling or disabling API outage circuit breakers.
5. Emitting automated promotion commands toward live execution.
